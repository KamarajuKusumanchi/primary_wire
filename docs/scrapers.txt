====== primary_wire: Scrapers ======

''config/scraper_config.yaml'' drives automated scraping for ~30 sources,
across five IR platforms (Q4, InvestorRoom, Notified, Investis Digital,
Adobe Experience Manager).
This file documents
each scraper script under ''src/'' in detail. See README.txt for the
high-level picture; this is the one to read before running a scraper, adding
a new source to an existing platform, or debugging one that broke.

===== scrape_all.py =====

Orchestrates every scraper configured in ''config/scraper_config.yaml'' in
one command, instead of invoking each scraper script by hand.

Usage:

  # Scrape every configured source for the current year
  python src/scrape_all.py

  # Preview only, nothing written
  python src/scrape_all.py --dry-run

  # One specific source, or one platform group
  python src/scrape_all.py --slug cdw
  python src/scrape_all.py --platform investorroom

  # Quick "is anything broken?" check: one random source per distinct
  # (scraper, extra CLI args) combination, instead of every source
  python src/scrape_all.py --smoke-test --dry-run

  # Same, but with a fixed seed for reproducible picks
  python src/scrape_all.py --smoke-test --dry-run --seed 42

''--smoke-test'' is also available as a single ''invoke'' command --
see [[tasks.txt]].

===== scrape_q4_ir.py =====

The main scraper. Collects press release links from any investor relations
site powered by Q4 Inc. -- a widely used IR platform. Many S&P 500 companies
use Q4, including Costco, CDW, Qualcomm, Corning, and ON Semiconductor. Q4
sites share a common URL structure and page layout, so a single scraper
handles all of them.

Because Q4 pages are rendered client-side, a plain HTTP request returns only
a "Loading..." placeholder. The scraper drives Chrome via Playwright to
render the full page, then parses the DOM with BeautifulSoup. No private API
is used -- it reads exactly what a human visiting the page would see.

Date extraction works in two stages:

  1. Listing-page parse (fast, zero extra requests): looks for a date in the
     HTML near each news link. Works on many Q4 themes (e.g. Costco).

  2. Detail-page fallback (opt-in via --fetch-detail-pages): for items where
     no date was found in stage 1, fetches each individual press release page
     and extracts the date from there. Required for some Q4 themes (e.g. CDW)
     where dates are not present in the listing-page HTML. Fetches are spaced
     by --polite-delay.

Usage:

  # Costco -- dates found on listing page, no detail fetches needed
  python src/scrape_q4_ir.py --dry-run

  # CDW -- dates only on detail pages; --fetch-detail-pages is required
  python src/scrape_q4_ir.py \
      --url https://investor.cdw.com/news/default.aspx \
      --fetch-detail-pages --dry-run

  # Any Q4 IR site by slug or ticker (looked up from sources.yaml)
  python src/scrape_q4_ir.py --slug cdw --fetch-detail-pages --dry-run
  python src/scrape_q4_ir.py --ticker CDW --fetch-detail-pages --dry-run

  # Scrape a specific year
  python src/scrape_q4_ir.py --year 2025

  # Scrape a range of years and output as JSON
  python src/scrape_q4_ir.py --start-year 2023 --end-year 2025 \
      --format json --output out.json --dry-run

  # Watch the browser and save rendered HTML for debugging
  python src/scrape_q4_ir.py --show-browser --debug-dump-html /tmp/page.html --dry-run

Chrome is assumed to already be installed. No ''playwright install'' download
is needed.

There are no company-specific wrapper scripts (e.g. a dedicated Costco or CDW
script) -- every Q4-powered IR site, including Costco and CDW, is scraped
through scrape_q4_ir.py directly via --slug or --ticker, as shown above.

===== scrape_investorroom.py =====

Collects press release links from any IR site powered by the InvestorRoom
platform (sold by Notified, formerly Intrado/West). Chipotle, Centene, and
IBM's newsroom are examples. Unlike Q4 sites, InvestorRoom pages are
server-side rendered -- a plain HTTP request returns full HTML, so no
Playwright is needed.

The listing page paginates by offset (''?l=100&o=100'', not a page number).
Detail pages come in three URL styles -- a legacy ''?item=NNNNN'' form, a
date-prefixed slug, and a bare slug with no date or item ID -- and this
scraper handles all three.

Date extraction prefers the date shown next to each link on the listing page
itself, since some sites' detail-page-style URLs embed a date that doesn't
always match the article's real publish date. For items where the listing
page has no date, ''--fetch-detail-pages'' fetches the detail page and reads
the date from the article header instead.

Usage:

  # Chipotle, dry-run
  python src/scrape_investorroom.py --dry-run

  # Any InvestorRoom site by slug, ticker, or URL
  python src/scrape_investorroom.py --slug chipotle --dry-run
  python src/scrape_investorroom.py --ticker CMG --dry-run
  python src/scrape_investorroom.py --url https://ir.chipotle.com/news-releases --dry-run

  # Restrict to a year or range
  python src/scrape_investorroom.py --year 2025 --dry-run

  # Fetch detail pages to resolve missing dates
  python src/scrape_investorroom.py --fetch-detail-pages --dry-run

Requires:

  pip install requests beautifulsoup4 lxml ruamel.yaml

===== scrape_notified.py =====

Collects press release links from any investor relations site powered by the
Notified platform (formerly Business Wire / Nasdaq IR), built on Drupal 10.
AbbVie and AMD are examples. Notified sites share a common listing-page and
detail-page structure, so a single scraper handles all of them.

The listing page paginates with a 0-based page index (''?page=0'',
''?page=1'', ...). There is no server-side year filter reflected in the URL --
the site's year dropdown reloads via a form POST -- so this scraper instead
paginates the full unfiltered listing and filters by year client-side. Dates
are read from the listing table (M/D/YY format, e.g. ''6/26/26''), falling
back to the date embedded in each row's summary text when needed.

curl_cffi is required (not plain ''requests''): these sites enforce TLS
fingerprinting that silently drops connections from the standard Python
requests stack, and curl_cffi impersonates Chrome's JA3/JA4 fingerprint to
get past it.

Usage:

  # AbbVie, dry-run
  python src/scrape_notified.py --dry-run

  # Any Notified/Drupal IR site by URL, slug, or ticker
  python src/scrape_notified.py --url https://investors.abbvie.com --dry-run
  python src/scrape_notified.py --slug abbvie --dry-run
  python src/scrape_notified.py --ticker ABBV --dry-run

  # Restrict to a year or range
  python src/scrape_notified.py --year 2025 --dry-run
  python src/scrape_notified.py --start-year 2023 --end-year 2025 --dry-run

Requires:

  pip install curl_cffi beautifulsoup4 lxml ruamel.yaml

===== scrape_notified_gated.py =====

A gated variant of scrape_notified.py for Notified/Drupal IR sites that are
additionally protected by bot mitigation (e.g. Akamai) strict enough to block
even a plain/headless request for the year-filter widget. It is not a
different platform -- the listing markup, detail-page URLs, and date format
are identical to scrape_notified.py. Defaults are set for The TJX Companies,
the first known site of this kind.

Where scrape_notified.py filters by year client-side by paginating the entire
unfiltered listing, this scraper instead obtains a year-filtered listing URL
directly, by resubmitting hidden tokens (a ''widget_hash''-prefixed
''_widget_id'' and a ''form_build_id'') exposed by the page's Drupal Views
year-filter widget -- much cheaper than paginating everything. Those tokens
only exist in the live, JS-rendered DOM, and the target site's bot mitigation
403s headless browser sessions specifically (confirmed against TJX by testing
headless vs. headed Chrome), so the one-time token-reading step always drives
a headed (non-headless) Chrome via Playwright. That means it needs an
environment with a display -- a desktop machine, or a VM with a virtual
display like Xvfb -- and will not run as-is on a headless server/CI box.
Once the year-filtered URL is in hand, Playwright is dropped entirely: the
listing itself is fetched and parsed with curl_cffi (Chrome TLS/JA3
impersonation) + BeautifulSoup, exactly as in scrape_notified.py.

Usage:

  # TJX, current year, dry-run
  python src/scrape_notified_gated.py --dry-run

  # Specific year
  python src/scrape_notified_gated.py --year 2024 --dry-run

  # By slug (site root looked up from sources.yaml; the gating-specific
  # form ID is still a hardcoded constant tuned for TJX)
  python src/scrape_notified_gated.py --slug tjx --dry-run

  # A gated site without a sources.yaml news_releases_path entry yet
  python src/scrape_notified_gated.py --slug robinhood \
      --news-releases-path press-releases --dry-run

Requires:

  pip install playwright curl_cffi beautifulsoup4 lxml
  playwright install chrome   # if Playwright can't find your Chrome install

Because the token-reading step needs a real display, this scraper is not yet
expected to run unattended on a headless CI box -- see the module docstring
for the known limitation.

===== scrape_investis.py =====

Collects press release links from any IR site powered by the Investis
Digital platform. Home Depot is the first confirmed site ("Delivered by
Investis Digital" in the page footer). Unlike Notified/InvestorRoom, where
one paginated feed spans the whole history, Investis puts each calendar
year at its own address (''/news-releases/<YYYY>''), paginated within the
year by a 1-based ''?page=N''. That means there's no year filter to
reverse-engineer -- the scraper just requests the exact year(s) it wants
directly -- but also no single feed to page through for a full-history
scan; instead, with no ''--year''/''--start-year'' given, the scraper walks
backward one calendar year at a time from the current year and stops the
first time a year comes back empty (the page shell renders with
"Information will appear here in due course." for out-of-range years),
capped by ''MAX_YEARS_BACK'' as a safety net.

Investis pages are server-side rendered, like InvestorRoom and unlike Q4,
so no Playwright is needed -- a plain GET on ''?page=N'' returns the same
HTML the "Load More News Releases" button fetches in a browser. Dates come
from the listing table's own Date column ("Mon DD, YYYY" text); if that's
unparseable, the detail-page URL's embedded ''MM-DD-YYYY'' segment is a
fallback, and ''--fetch-detail-pages'' is available as a last resort.

Usage:

  # Home Depot, full history, dry-run
  python src/scrape_investis.py --dry-run

  # Any Investis Digital site by URL, slug, or ticker
  python src/scrape_investis.py --url https://ir.homedepot.com --dry-run
  python src/scrape_investis.py --slug home-depot --dry-run
  python src/scrape_investis.py --ticker HD --dry-run

  # Restrict to a year or range (skips the full-history scan)
  python src/scrape_investis.py --year 2025 --dry-run
  python src/scrape_investis.py --start-year 2023 --end-year 2025 --dry-run

  # Fetch detail pages to resolve any dates the listing page couldn't parse
  python src/scrape_investis.py --fetch-detail-pages --dry-run

Requires:

  pip install curl_cffi beautifulsoup4 lxml ruamel.yaml

curl_cffi is used here as a precaution (the site sits behind Cloudflare)
rather than a confirmed requirement the way it is for scrape_notified.py's
AbbVie default -- see the module docstring if plain ''requests'' turns out
to work fine and this needs revisiting.

===== scrape_aem_bny.py =====

Collects press release links from BNY's (The Bank of New York Mellon
Corporation) investor-relations site, which is built on Adobe Experience
Manager (AEM).

Until 2026-08 this lived in one shared scrape_aem.py alongside CME Group,
on the theory that "same underlying platform => same scraper". Both sites
really do fingerprint as AEM (see src/reporting/detect_ir_platform.py),
but AEM is a page-authoring platform, not a prepackaged press-release-
listing widget: every AEM site's IR team builds its own bespoke listing
markup, pagination control, and filter UI on top of it, and BNY's and
CME's turned out to share almost none of that -- different card markup,
different pagination widgets, and (see below) BNY has a working in-page
year filter while CME doesn't. They're now two separate scrapers; see
scrape_aem_cme.py below for the CME side.

AEM listings render via JS, so -- like Q4 -- this scraper drives Chrome via
Playwright, then parses the rendered DOM with BeautifulSoup. BNY's own
press-release cards are a bespoke widget (not Adobe's documented Core
Components), and its pagination is a numbered widget that *replaces* the
visible card list on every click rather than appending to it, so this
scraper parses and collects items after each page loads instead of taking
one snapshot at the end. BNY also exposes a real in-page "Filter by" year
control, which this scraper drives directly (server-side filtering) rather
than paginating through the entire unfiltered history and filtering
client-side.

''--item-selector'' overrides the built-in selector cascade if BNY's own
markup changes out from under this scraper.

Usage:

  # Dry-run
  python src/scrape_aem_bny.py --dry-run

  # By slug, ticker, or URL
  python src/scrape_aem_bny.py --slug bny --dry-run
  python src/scrape_aem_bny.py --ticker BNY --dry-run
  python src/scrape_aem_bny.py \
      --url https://www.bny.com/corporate/global/en/investor-relations/press-releases.html \
      --dry-run

  # Restrict to a year or range (drives the in-page year filter directly)
  python src/scrape_aem_bny.py --year 2025 --dry-run
  python src/scrape_aem_bny.py --start-year 2023 --end-year 2025 --dry-run

  # Fetch detail pages to resolve any dates the listing page didn't expose
  python src/scrape_aem_bny.py --fetch-detail-pages --dry-run

  # Watch the browser and save the rendered HTML for debugging selectors
  python src/scrape_aem_bny.py --show-browser --debug-dump-html /tmp/bny.html --dry-run

  # Override the item-card CSS selector if BNY's markup doesn't match the
  # built-in guesses
  python src/scrape_aem_bny.py --item-selector ".my-custom-card" --dry-run

Requires:

  pip install playwright beautifulsoup4 lxml

Chrome is assumed to already be installed. No ''playwright install'' download
is needed.

===== scrape_aem_cme.py =====

Collects press release links from CME Group's investor-relations /
media-room site, also built on Adobe Experience Manager (AEM) -- see
scrape_aem_bny.py above for why this is a separate scraper from BNY's
despite sharing the same underlying platform.

Same Playwright-drives-Chrome-then-BeautifulSoup-parses-the-DOM shape as
scrape_aem_bny.py, but nothing about the actual markup is shared: CME's
cards are ''#cmeSearchFilterResults > li'' (not Adobe Core Components,
not BNY's ''.list-item-tile''), its dateline text is day-first ("6
August, 2026"), its pagination is a jQuery "bootpag" widget rather than
BNY's numbered-label widget, and pages are 30 cards each rather than 10.

Unlike BNY, CME has no confirmed working in-page year filter. By default
this scraper paginates the unfiltered, newest-first listing and stops
once an entire page is older than the requested year -- correct, but
expensive for an old year (reaching October 2023 from today's listing
took 11 pages / ~330 cards in testing). CME does have a free-text
date-range picker in its "Refine Your Search" panel; ''--use-date-filter''
drives it directly instead, but that code path is new and UNVERIFIED
against the live site -- it's opt-in for that reason, and falls back
automatically to the unfiltered walk if the site doesn't visibly respond
to it. Verify with ''--show-browser --use-date-filter'' before relying on
it for a real run.

Usage:

  # Dry-run
  python src/scrape_aem_cme.py --dry-run

  # By slug, ticker, or URL
  python src/scrape_aem_cme.py --slug cme --dry-run
  python src/scrape_aem_cme.py --ticker CME --dry-run
  python src/scrape_aem_cme.py \
      --url https://www.cmegroup.com/media-room/press-releases.html \
      --dry-run

  # Restrict to a year (unfiltered walk-and-stop by default)
  python src/scrape_aem_cme.py --year 2024 --dry-run

  # Same, but try the (unverified) in-page date-range filter first --
  # verify with --show-browser before trusting this for a real run
  python src/scrape_aem_cme.py --year 2024 --use-date-filter --show-browser --dry-run

  # Fetch detail pages to resolve any dates the listing page didn't expose
  python src/scrape_aem_cme.py --fetch-detail-pages --dry-run

  # Watch the browser and save the rendered HTML for debugging selectors
  python src/scrape_aem_cme.py --show-browser --debug-dump-html /tmp/cme.html --dry-run

  # Override the item-card CSS selector if CME's markup doesn't match the
  # built-in default
  python src/scrape_aem_cme.py --item-selector ".my-custom-card" --dry-run

Requires:

  pip install playwright beautifulsoup4 lxml

Chrome is assumed to already be installed. No ''playwright install'' download
is needed.

===== Guidelines for automated contributions =====

See README.txt's "Guidelines for automated contributions" section -- every
scraper above already follows it (polite delays, once-per-day runs, backing
off on errors). Read it before adding a new scraper or a ''--polite-delay''
override.

===== Adding a new scraper (or a new source to an existing one) =====

Most new sources fit an existing platform -- check the platform fingerprints
in the relevant scraper's module docstring first (e.g. ''?item=NNNNN'' or
''/news-releases'' URLs for InvestorRoom, a Drupal 10 generator meta tag for
Notified). ''src/reporting/detect_ir_platform.py'' can classify a source's
platform automatically -- see [[reporting.txt]]. Adding such a source is
usually just a new ''sources.yaml'' entry plus a ''config/scraper_config.yaml''
entry, not a new script.

A genuinely new platform:

  1. Add one entry to PLATFORMS in ''src/utils/sources_utils.py'' -- name,
     listing-path field/default, scraper module name, one-line description.
     This is now the single source of truth for the platform's name; see
     that dict's own comment.
  2. Write ''scrape_<platform>.py'', following the pattern of the existing
     ones: share argparse/date/output plumbing via ''utils/scrape_utils.py'',
     share ''sources.yaml'' lookups via ''utils/sources_utils.py'', and import
     its listing-path default from the PLATFORMS entry you just added
     (e.g. ''INVESTIS_DEFAULT_NEWS_RELEASES_PATH'') instead of redefining it.
  3. Add a ''_check_<platform>()'' fingerprint test and a matching
     ''PLATFORM_<X>'' constant (added to ''DETECTOR_PLATFORMS'') in
     ''src/reporting/detect_ir_platform.py''. If you forget this step (or
     step 1), that module's ''_assert_platforms_registered()'' raises at
     import time rather than letting the two lists silently disagree --
     run any command in that script, or just ''python -c "import
     reporting.detect_ir_platform"'', and a mismatch will fail loudly.
  4. Add a one-line bullet plus a full section to this file (not
     README.txt) documenting how the scraper actually works -- this part
     genuinely can't be generated from the registry, since it's the "how",
     not just the "what".

''python src/reporting/detect_ir_platform.py --list-platforms'' always
prints the current, live PLATFORMS registry, so it's the thing to check
(not this file's prose) if you're unsure whether a platform is registered
yet.
