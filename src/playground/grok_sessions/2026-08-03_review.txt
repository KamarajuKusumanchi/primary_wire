### Scalability & extensibility

**What already helps**

- Config-driven selection (`scraper_config.yaml`) + durable facts in `sources.yaml`.
- Smoke-test grouping by `(module, args, durable signature fields)` is a clever way to cover code paths without scraping everything.
- Batched `merge_scraped_items()` at the end of `scrape_all` is the right shape for future parallelism (no per-source CSV locking).
- Shared `finalize_and_output`, `parse_year_args`, `add_common_args`, etc.

**What limits growth**

| Area | Current state | Suggestion |
|------|---------------|------------|
| Scraper modules | 750–1,200 lines each; lots of duplicated CLI / resolve-source / session / preview plumbing | Extract a thin `BaseScraper` (or composition helpers) that owns argparse, source resolution, year filtering, and the `scrape_and_filter` → `finalize_and_output` pipeline. Platform code only implements “fetch + parse listing(s)”. |
| `NewsItem` | Base in `scrape_utils`; every scraper re-declares a subclass; only Q4 adds a real field (`category`) | Drop empty subclasses; use the base class (or a typed dict / pydantic model). Keep Q4’s extra field via composition or a single optional `extra: dict`. |
| Platform detection | Large standalone script (`detect_ir_platform.py` ~1,200 lines) | Useful; consider making the detection functions the same ones the scrapers themselves use for “am I on the right platform?” sanity checks. |
| Concurrency | Documented as present; implemented as sequential | Implement `ThreadPoolExecutor` (or `ProcessPool` for Playwright) with a configurable worker count and per-source timeout. The batched merge already supports it. |
| Storage | One CSV per calendar day under `data/YYYY/` | Fine at current scale. For multi-year, multi-source growth consider Parquet/SQLite + the same daily files as a view, or at least an index of (slug, url) → path. |
| Rate limiting / politeness | Per-scraper `--polite-delay` + `between_delay` in `scrape_all` | Centralize a token-bucket or simple shared delay policy so parallel runs stay polite. |

### Design & code improvements

1. **Unify the scraper entry point**
   All six scrapers already follow roughly the same shape:
   - `build_arg_parser()`
   - `resolve_source` / identity helpers
   - `scrape(...)` / year loops
   - `scrape_and_filter(argv, write=True)`
   - thin `main()`
   Move the common argparse flags, logging setup, source resolution, and the final `finalize_and_output` call into a shared helper (or a small class). Platform modules then only supply parsers and the core scrape function.

2. **Session / browser lifecycle**
   Creating a fresh `curl_cffi` session or Playwright browser per source is correct for isolation. Document the contract once in `scrape_utils` / `scrape_notified_utils` and stop repeating the same paragraph in every file.

3. **Reduce Playwright surface**
   Q4 and AEM (and gated Notified) need a browser. Consider a small shared “browser context” helper that owns launch options, headless fallback, debug-dump-html, and polite delay so each scraper does not re-implement `_launch_browser` variants.

4. **Config validation**
   There is already a consistency check between `scraper_config.yaml` and detected platforms. Extend it to:
   - every configured slug exists in `sources.yaml`
   - durable fields referenced by `DURABLE_SIGNATURE_FIELDS` actually exist on those sources
   - no duplicate slugs across platform groups

5. **Typing & packaging**
   Add `py.typed`, explicit return types on the public scraper functions, and consider making the package installable (`pip install -e .`) so tests and `invoke` do not rely on `sys.path` hacks.

6. **Tests**
   Good coverage of date parsing and a few platform edge cases. Add:
   - contract tests that every scraper module exports `scrape_and_filter`
   - a cheap offline fixture-based test per platform (saved HTML dumps already seem partially supported via `--debug-dump-html`)
   - parallel-safety tests once concurrency lands

### Worth refactoring

- **Empty `NewsItem` subclasses** in InvestorRoom, Notified, Notified-gated, Investis, AEM — they add noise and force every helper to accept “some NewsItem-like thing”. Keep only the Q4 subclass (or promote `category` to an optional base field).
- **Duplicated “new session / not a singleton” blocks** across `scrape_investis`, `scrape_investorroom`, `scrape_notified*`, and `scrape_notified_utils`.
- **CLI construction** — almost every scraper re-implements year / dry-run / format / output / data-dir / verbose flags. `add_common_args` exists; push more of the boilerplate into it.
- **`scrape_all.run_scraper`** already does dynamic import + `scrape_and_filter(..., write=False)`. That is the right seam; lean on it harder and shrink each scraper’s `main`.
- **Reporting scripts** are solid but long (`detect_ir_platform` especially). Split detection heuristics from the CLI/reporting driver.

### Comments that do not match the code

Several places state that `scrape_all.py` already runs sources concurrently in a thread pool. The actual loop is sequential (`for ... in sources: ... time.sleep(...); run_scraper(...)`). Examples:

- `src/utils/scrape_notified_utils.py` (`new_session` docstring): “scrape_all.py runs sources concurrently in a thread pool (one worker per source)”
- Same claim in `scrape_investis.py`, `scrape_investorroom.py`, `scrape_notified.py`, `scrape_notified_gated.py`
- `scrape_utils.finalize_and_output` docstring discusses concurrent writes as if they already happen

`scrape_all.py`’s *own* docstring is accurate: it says the loop is still sequential and the batched merge is what *will* enable a future `ThreadPoolExecutor`. The other files over-state the present.

Minor secondary drift:

- Some comments still talk about “extra args” as the only smoke-test differentiator; the code correctly also factors in `DURABLE_SIGNATURE_FIELDS` (e.g. `needs_detail_page_dates`).
- A few older comments about CDW needing aria-label / detail-page dates have been partially superseded by later DOM-climbing fixes; the long module docstrings still carry historical narrative that is useful but easy to misread as current behavior.
