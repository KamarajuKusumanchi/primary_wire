## On speed

`scrape_all.py` runs every configured source **serially, in-process** (`run_scraper()` calls each module's `main()` one at a time). Given each source is a different company's domain, running them one after another gains you nothing from a politeness standpoint — the 10-30s "per-domain" spacing rule only matters *within* a single site's pagination, not *across* sites. Notably, the codebase already has the pattern for this: `detect_ir_platform.py` uses `concurrent.futures.ThreadPoolExecutor` to fetch ~167 sources in parallel. That same pattern hasn't been applied to `scrape_all.py`, where it would matter more, since Q4 sources launch a full Playwright browser each (real wall-clock cost). Parallelizing scrape_all.py across sources (thread pool, one source per worker, keeping the polite delay only inside each source's own loop) is probably the single biggest speed win available, and the codebase already proves the team knows how to do it.
